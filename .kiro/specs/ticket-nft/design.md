# Design: Marketplace Contract (Member 2)

**Status:** CONFIRMED (2 Nov 2026). Implements `requirements.md`. Reads TicketNFT through `ITicketNFT` and `IERC721`; does not change TicketNFT.

## 1. Overview

```
Seller ── listTicket(tokenId, price) ──────────┐
Seller ── cancelListing(tokenId) ──────────────┤
Buyer  ── buyListing{value: price}(tokenId) ───┤        ┌──────── isTransferable / getResaleCap
Seller ── withdrawProceeds() ──────────────────┤        │         getTicket / ownerOf  (reads)
                                               ▼        ▼
                                        ┌─────────────────┐  transferByMarketplace(seller, buyer, id)
                                        │   Marketplace   │ ──────────────────────────────────────►┌───────────┐
                                        │ (ReentrancyGuard)│  receiveResaleFee{value: fee}(eventId)  │ TicketNFT │
                                        └─────────────────┘ ──────────────────────────────────────►└───────────┘
                                                                         ▲
Admin(TicketNFT) ── grantRole(MARKETPLACE_ROLE, marketplace) ────────────┘
```

The NFT never leaves the seller's wallet until the sale (no escrow). A listing is only a record that the holder is willing to sell at `price`.

**Money flow of one sale** (`P` = price, `F` = fee):

| Step | Amount | Destination |
|---|---|---|
| Buyer pays | `P` | Marketplace (`msg.value`) |
| Fee | `F = floor(P * feeBps / 10_000)` | `TicketNFT` resale-fee balance of the event (organizer withdraws it) |
| Proceeds | `P - F` | `pendingProceeds[seller]` (seller pulls it) |

Worked example (ticket 0.01 ETH, `resaleCapBps = 11000`, `feeBps = 500`): cap = 0.011 ETH; sale at 0.011 ETH gives fee 0.00055 ETH and seller proceeds 0.01045 ETH.

## 3. Data model

```solidity
struct Listing { address seller; uint256 price; }   // seller == address(0) means "no listing"

uint16 public constant MAX_FEE_BPS = 1_000;          // 10%
uint16 private constant BPS_DENOMINATOR = 10_000;    // (uint256 in math)

address public immutable ticketNft;                  // implements IMarketplace.ticketNft()
uint16  public immutable feeBps;                     // implements IMarketplace.feeBps()

mapping(uint256 tokenId => Listing) private _listings;
mapping(address seller => uint256)  private _pendingProceeds;
```

Notes:
- `tokenId` is unique across all events in TicketNFT, so it is a sufficient listing key. [OD-M7]
- Public `immutable`/`constant` variables can implement the external getters of `IMarketplace` using `override`.
- There is no list of listings; clients use events. [OD-M11]

## 4. Functions

### 4.1 `listTicket(uint256 tokenId, uint256 price)`

| # | Check | Error |
|---|---|---|
| 1 | `price > 0` | `ZeroPrice()` |
| 2 | `ITicketNFT.isTransferable(tokenId)` | `TicketNotTransferable(tokenId)` |
| 3 | `IERC721.ownerOf(tokenId) == msg.sender` | `NotTicketHolder(tokenId, msg.sender)` |
| 4 | `price <= getResaleCap(tokenId)` | `PriceAboveCap(tokenId, price, cap)` |
| 5 | `_listings[tokenId].seller != msg.sender` | `AlreadyListed(tokenId)` |

Effects: `_listings[tokenId] = Listing(msg.sender, price)`. Then read `eventId = getTicket(tokenId).eventId` and emit `Listed`.
Order matters: check 2 comes before 3 because `isTransferable` never reverts, while `ownerOf` reverts for burned or unminted tokens. Check 5 only blocks the *same* seller; a stale listing from another address is overwritten.

### 4.2 `cancelListing(uint256 tokenId)`

`seller == 0` → `NotListed`; `seller != msg.sender` → `NotSeller`; `delete _listings[tokenId]`; emit `ListingCanceled`. No external calls.

### 4.3 `buyListing(uint256 tokenId) payable nonReentrant`

| # | Step | On failure |
|---|---|---|
| 1 | load listing; `seller != 0` | `NotListed(tokenId)` |
| 2 | `msg.sender != seller` | `CannotBuyOwnListing()` |
| 3 | `msg.value == price` | `IncorrectPayment(price, msg.value)` |
| 4 | `isTransferable(tokenId)` | `TicketNotTransferable(tokenId)` |
| 5 | `ownerOf(tokenId) == seller` | `StaleListing(tokenId)` |
| 6 | read `eventId = getTicket(tokenId).eventId` | — |
| 7 | **effects:** `fee = price * feeBps / 10_000`; `_pendingProceeds[seller] += price - fee`; `delete _listings[tokenId]` | — |
| 8 | **interaction:** `transferByMarketplace(seller, msg.sender, tokenId)` | bubbles up TicketNFT error |
| 9 | **interaction:** `if (fee > 0) receiveResaleFee{value: fee}(eventId)` | bubbles up TicketNFT error |
| 10 | emit `Sold(tokenId, eventId, msg.sender, seller, price, fee)` | — |

Notes:
- No cap re-check: the cap is locked after the first sale (see R4.9), so the listing-time check holds forever.
- `transferByMarketplace` uses an internal `_transfer` (no `onERC721Received` call), so a contract buyer cannot re-enter. `nonReentrant` still guards against a malicious future TicketNFT-side change and keeps the pattern uniform.
- Errors raised by TicketNFT (for example `AccessControlUnauthorizedAccount` when the role was revoked) bubble up unchanged; clients decode them with the TicketNFT ABI.
- The fee is rounded down, so the organizer can lose less than 1 wei per sale; the seller gets the remainder. Document in NatSpec.

### 4.4 `withdrawProceeds() nonReentrant`

`amount = _pendingProceeds[msg.sender]`; `amount == 0` → `NoProceeds()`; `_pendingProceeds[msg.sender] = 0`; `(ok,) = msg.sender.call{value: amount}("")`; `!ok` → `EthTransferFailed()`; emit `ProceedsWithdrawn`.

### 4.5 Views

| Function | Returns |
|---|---|
| `getListing(tokenId)` | `Listing` (zero struct if none) |
| `pendingProceeds(seller)` | `uint256` |
| `quoteSale(price)` | `(fee, sellerAmount)`, same formula as `buyListing`, never reverts |
| `ticketNft()` / `feeBps()` / `MAX_FEE_BPS()` | configuration |

### 4.6 Constructor

`ticketNft_ == 0` → `ZeroAddress()`; `feeBps_ > MAX_FEE_BPS` → `InvalidFee()`. Recommended demo deployment value: `feeBps_ = 500` (5%). [OD-M2]

## 5. Lifecycle of a listing

```
            listTicket                      buyListing (ok)
 (none) ─────────────────► LISTED ───────────────────────────► (none)   [ticket moves to buyer]
    ▲                       │  │
    │        cancelListing  │  └── event starts / cancelled / ticket used, revoked, refunded
    └───────────────────────┘        → listing stays in storage but cannot be bought
                                       (TicketNotTransferable); seller may still cancel
```

A listing is **purchasable** for a client when all three hold: a listing exists, `isTransferable(tokenId)` is true, and `ownerOf(tokenId) == listing.seller`. The frontend and indexer should show only purchasable listings.

## 6. Money invariant

After every successful call:

`address(this).balance >= Σ pendingProceeds[seller]`

It is an equality unless someone force-sends ETH (`selfdestruct`), which the contract cannot prevent. Reason for equality in normal operation: ETH enters only through `buyListing`; the fee part is forwarded to TicketNFT in the same transaction and the rest is credited to exactly one seller; ETH leaves only through `withdrawProceeds`, after the credit is zeroed. Tests must assert this after mixed sequences (see TODO group G).

## 7. Custom errors

| Error | Used in |
|---|---|
| `ZeroAddress()` | constructor |
| `InvalidFee()` | constructor |
| `ZeroPrice()` | `listTicket` |
| `NotTicketHolder(uint256 tokenId, address caller)` | `listTicket` |
| `TicketNotTransferable(uint256 tokenId)` | `listTicket`, `buyListing` |
| `PriceAboveCap(uint256 tokenId, uint256 price, uint256 cap)` | `listTicket` |
| `AlreadyListed(uint256 tokenId)` | `listTicket` |
| `NotListed(uint256 tokenId)` | `cancelListing`, `buyListing` |
| `NotSeller(uint256 tokenId, address caller)` | `cancelListing` |
| `CannotBuyOwnListing()` | `buyListing` |
| `IncorrectPayment(uint256 expected, uint256 sent)` | `buyListing` |
| `StaleListing(uint256 tokenId)` | `buyListing` |
| `NoProceeds()` | `withdrawProceeds` |
| `EthTransferFailed()` | `withdrawProceeds` |

`ZeroAddress`, `NotTicketHolder`, `TicketNotTransferable`, `IncorrectPayment`, and `EthTransferFailed` have the same signature as in TicketNFT, so both ABIs can be merged in one decoder. The proceeds error is `NoProceeds()` (not `NothingToWithdraw`) because TicketNFT already defines `NothingToWithdraw(uint256)` with a different signature.

## 8. Events

| Event | Fields (`indexed` marked) | Emitted by |
|---|---|---|
| `Listed` | `tokenId` (indexed), `eventId` (indexed), `seller` (indexed), `price` | `listTicket` |
| `ListingCanceled` | `tokenId` (indexed), `seller` (indexed) | `cancelListing` |
| `Sold` | `tokenId` (indexed), `eventId` (indexed), `buyer` (indexed), `seller`, `price`, `fee` | `buyListing` |
| `ProceedsWithdrawn` | `seller` (indexed), `amount` | `withdrawProceeds` |

Active listings for an indexer: `Listed` minus later `ListingCanceled` or `Sold` for the same `tokenId`, then filtered by the purchasable rule in §5. TicketNFT's own `Transfer` event is also emitted on every sale.

## 9. Security notes

1. **Consent:** a ticket can only be sold through a listing created by its current holder; there is no path for a third party to sell someone else's ticket.
2. **Reentrancy:** `buyListing` and `withdrawProceeds` are `nonReentrant`; state is updated before every external call.
3. **Pull payments:** a seller contract that rejects ETH or burns gas cannot block buyers.
4. **Cap integrity:** price ≤ cap is enforced at listing time; the fee is inside the price, so the buyer never pays above the cap.
5. **Kill switch:** the TicketNFT Admin can revoke `MARKETPLACE_ROLE`; after that no sale can complete, but `cancelListing` and `withdrawProceeds` keep working, so no funds are trapped.
6. **No admin:** no owner, setter, pause, or upgrade, so there is no privileged function to compromise.
7. **Known limitations (documented in the integration doc):**
   - No per-wallet limit on resale purchases [OD-M10].
   - TicketNFT fully trusts any `MARKETPLACE_ROLE` holder; a second marketplace granted the role could move tickets. This could also leave a stale listing that becomes live again if the ticket returns to its old seller; the old price stays valid and the seller can cancel it.
   - Fee rounding favors the seller by less than 1 wei per sale.
   - ETH can be force-sent to the contract; the invariant is `>=`.
   - Revealed listing prices are public; there is no bid/offer or front-run protection beyond the exact-payment rule (a price change makes a pending buy revert).
